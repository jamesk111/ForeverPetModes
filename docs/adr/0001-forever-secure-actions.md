# ADR 0001 · Apply a profile through one out-of-combat player click

**Accepted November 21, 2026** for v0.1.0. Live-client acceptance is open.

## Evidence for the target client

The installed product's build manifest identified `wowf` version `1.60.1.71037`. The Forever UI mirror has that exact build at commit `734f065329cff4992835b01a84f210a297db91b6`. An independent live Forever add-on records interface `16001`, also present in the locally installed Forever add-on manifests. The module manifest declares that interface and the Camelot load filter. [Pinned UI export](https://github.com/Gethe/wow-ui-source/tree/734f065329cff4992835b01a84f210a297db91b6) · [Live interface provenance](https://github.com/rik-wow/RikUI)

The shared pet bar reads ten slots with `GetPetActionInfo`. The fields consumed here are token/name, texture, selected flag, autocast allowed/enabled and spell ID. The client names native buttons `PetActionButtonN`. It handles a left click as a pet action and a right click as an autocast toggle. The native bar subscribes to pet-bar and unit events. [Pet bar](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_ActionBar/Shared/PetActionBar.lua) · [Button construction](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_ActionBar/Shared/ActionBar.lua)

A Forever beta player reported that `/petdefensive` failed while clicking their ninth native button worked. Build 71037 contains a conditional registration for the defensive command and a separate defensive-assist handler. Source presence alone cannot establish whether a particular pet responds. The addon discovers the Defensive slot on each pet and treats unrecognized stance tokens as unknown. [First-hand report](https://us.forums.blizzard.com/en/wow/t/hunter-pet-ai-supposed-to-be-this-janky/2371362) · [Secure slash commands](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_ChatFrameBase/Shared/SlashCommands.lua)

A live Forever hunter-bar capture identifies the button labeled Defensive as `PET_MODE_DEFENSIVEASSIST`, alongside the distinct Assist and Passive controls. v0.1.2 recognizes that token for both binding and readback. [Live pet-bar capture](https://us.forums.blizzard.com/en/wow/t/hunter-pets-week-1-consolidated-bug-feedback-thread/2405538/4)

## Decision and tradeoffs

Use Blizzard's `InsecureActionButtonTemplate`, which checks combat lockdown before dispatching to the secure action handler. Set its macro attributes outside lockdown. A real left-button release runs a fixed-format macro. Each line is conditional on a living pet, no modifier and no combat. The stance line targets only a numbered native pet button. The native click command checks the target's access constraints and scripted-input restrictions. The autocast commands request explicit on/off through the game's slash handlers. Only an ability name read from the live bar can enter those lines. The binding is cleared if a rule cannot be resolved, conflicts with another rule or exceeds the conservative macro budget. [Button template](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.xml) · [Macro dispatcher](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.lua) · [Autocast handlers](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_ChatFrameBase/Mainline/SlashCommandsOverrides.lua)

Native commands can succeed independently. The addon therefore reads the pet bar again and offers manual steps for any remaining differences. It performs no automatic retry. The bar-only approach requires each configured ability and stance to be present and readable. A control restricted by the client stays restricted. A standard secure visibility driver handles combat and pet-presence filters. An instance-filter change during lockdown takes effect at the next safe refresh.

## v0.2.0 preflight and presentation

The settings picker edits the existing saved rule list, preserving rank IDs and profiles. Button availability and active matching are separate. An active pet profile can still be locked in combat. Before binding a click, the addon checks the native stance target and configured abilities. When the stance already matches, an inaccessible stance button can be omitted. When a full macro is too long, only differing commands are retained and each keeps its original guard. A pet change invalidates pending confirmations.

## Blizzard policy review

The release is free, readable Lua with data and a license. It uses WoW's addon loader and UI APIs. Event callbacks read state and repaint. Profile application requires a deliberate hardware click. The package contains no external controller, advertising, donation prompts, or executable installer. This design follows the published add-on policy and the EULA restrictions on unauthorized automation. Blizzard retains authority over add-on behavior and can change its rules or APIs. Repeat the source and policy review after a relevant change.
