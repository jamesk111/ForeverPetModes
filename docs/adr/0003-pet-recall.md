# ADR 0003 · Direct pet commands, profile shortcuts and care

**Local preview, November 24, 2026.**

Follow issues the game's Follow command on a player click. A fixed action has no dependency on pet-bar slot order, the selected profile, the pet's previous target or a spell name. It preserves the player's stance and autocast choices. Defensive behavior can engage a target again, and movement depends on the pet being able to reach its owner.

The button inherits Blizzard's secure action template. The addon sets its left-click macro to `/petfollow [@pet,exists,nodead]` while building the panel outside lockdown. The Forever command handler evaluates the condition and calls the game's Follow action. The addon leaves the binding fixed during combat. The game controls execution. The ordinary profile buttons retain their out-of-combat bindings. [Forever secure template](https://github.com/Gethe/wow-ui-source/blob/c01a87b549bbc19e0f284c1616d18654c91297de/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.xml) · [Forever Follow handler](https://github.com/Gethe/wow-ui-source/blob/c01a87b549bbc19e0f284c1616d18654c91297de/Interface/AddOns/Blizzard_ChatFrameBase/Shared/SlashCommands.lua)

Attack and Stay use the same fixed-button design. Each command resolves its current Blizzard pet-bar slot to display the corresponding native shortcut. WoW formats the compact key on the button and the long key on hover. This tracks player changes to pet slots and keybindings. The prior Recall visibility preference now controls the command group. [Native pet-bar binding display](https://github.com/Gethe/wow-ui-source/blob/c01a87b549bbc19e0f284c1616d18654c91297de/Interface/AddOns/Blizzard_ActionBar/Shared/PetActionBar.lua)

Bindings.xml exposes optional CLICK bindings for the commands and four stable, named profile favorites. Players assign keys in WoW. Each profile can own one favorite and each favorite can have one owner. Reassignment or deletion clears stale actions. Profile macros retain their existing unmodified, out-of-combat click guards.

The primary care button uses a single guarded cast with learned spells in dead, living and absent pet order. A state driver selects its caption using the same conditions. One click binding therefore follows Mend, Revive and Call. The health bar accepts the native percentage directly, including values the game restricts to display. The detail tooltip formats only readable numbers. Both Call and Revive are offered with an absent pet because its corpse may have disappeared. Feed opens a bag-item picker. The picker uses C_PetInfo.CanPetEatItem, the same check as the game’s bag UI. Only a food click arms the secure Feed Pet spell and its target-bag and target-slot attributes. It rechecks the item in that slot immediately before the click and clears the target afterward. Spell casting and movement require live-client verification.

The panel groups lasting profile choices on the left. Compact profiles share clickable seams while keeping their own binding targets and match indicators. The right column starts with pet identity and health, followed by native commands and contextual care. Each visible row starts at the same left edge. The open divider offers a full-height click target. Folding removes the complete right column and divider so the profiles have equal side margins. The same toggle moves into its own space at the right end of the drag strip. Retaining the height and left edge keeps the profile and ability rows stationary.

The local Forever build is 1.60.1.71091. Its mirrored happiness UI, pet API, unit event documentation, secure templates and slash-command handler match the reviewed source file by file. [Forever happiness indicator](https://github.com/Gethe/wow-ui-source/blob/c01a87b549bbc19e0f284c1616d18654c91297de/Interface/AddOns/Blizzard_FrameXML/PetHappiness.lua)

When Call is learned and pet care is enabled, complementary secure visibility drivers switch between the normal panel and an independently sized summon button anchored at its top-left. Both honor the same class, combat, instance and manual-hide rules. The named card uses Forever’s current stable slot (1), with a per-character identity cache when the pet is absent. Shift-click keeps recovery of a missing corpse available on the same card.
